# Optional reset transaction boundary

Monitoring, quota refresh, status, forecasts and advice never call redemption.
There is no production reset adapter or default enabled CLI submission command.
The injected engine remains for explicitly verified host integrations only.

An exact effect/cost/account/contract approval expires within five minutes. The
UUID is persisted before dispatch and reused as the logical operation identity.
PREPARED can be cancelled; SUBMITTING/ACCEPTED cannot be cancelled into a new retry.
Duplicate submission calls reconcile only. No same-key retry is enabled without
an independently verified endpoint contract; no second key can bypass an in-flight
account operation. Lost receipts and process death retain uncertainty.

Accepted/already-redeemed receipts require keyed readback. No-credit, nothing-to-
reset and ineligible are non-mutating declined outcomes. A verified operation does
not imply all windows reset: `changed_buckets` and `all_windows_reset` remain null
when a host supplies no independently bound per-bucket readback. Quota observation
must confirm affected buckets separately. Existing turn/start no-blind-replay
rules are unchanged. No real reset was executed during offline verification.
